## 1. What We're Building

The `HabitRepository` inherits 5 CRUD methods from `BaseRepository[Habit]` and adds 7 habit-specific queries:

| # | Method | What It Does | SQL Equivalent |
|---|--------|-------------|----------------|
| — | `create(**kwargs)` | Insert a habit | `INSERT INTO habits (...)` |
| — | `get_by_id(id)` | Get by UUID | `WHERE id = ?` |
| — | `get_all(offset, limit)` | Paginated list | `LIMIT ? OFFSET ?` |
| — | `update(id, **kwargs)` | Update fields | `UPDATE habits SET ... WHERE id = ?` |
| — | `delete(id)` | Hard delete | `DELETE FROM habits WHERE id = ?` |
| 1 | `get_user_habits(user_id, include_archived)` | All habits for a user | `WHERE user_id = ? AND NOT archived ORDER BY sort_order` |
| 2 | `get_user_habit(user_id, habit_id)` | One habit, user-scoped | `WHERE id = ? AND user_id = ?` |
| 3 | `name_exists_for_user(user_id, name)` | Duplicate check | `COUNT(*) WHERE user_id = ? AND name = ?` |
| 4 | `count_active_habits(user_id)` | Count for limit check | `COUNT(*) WHERE user_id = ? AND NOT archived` |
| 5 | `get_next_sort_order(user_id)` | Next position | `MAX(sort_order) + 1` |
| 6 | `reorder_habits(user_id, habit_ids)` | Batch reorder | Multiple `UPDATE sort_order` |
| 7 | `archive_habit(user_id, habit_id)` | Soft delete | `UPDATE SET is_archived = true` |

### Comparison with Auth Repository

| Feature | UserRepository (Auth) | HabitRepository (Habits) |
|---------|----------------------|--------------------------|
| Custom methods | 3 | 7 |
| User scoping | Only `get_active_by_id` | ALL methods require user_id |
| Soft delete | Via User.is_active | Via Habit.is_archived |
| Batch operations | None | `reorder_habits` (updates multiple rows) |
| Counting | None | `count_active_habits` |
| Aggregate functions | None | `MAX(sort_order)` with `COALESCE` |

## 2. File: `repository.py` — Full Source Code

### Type This Code: `backend/app/modules/habits/repository.py`

```python
# ============================================================================
# Habits Module — Repository (Data Access Layer)
# ============================================================================
# WHAT THIS FILE DOES:
#   All database queries for habits. Extends BaseRepository with
#   habit-specific queries: get by user, check duplicates, reorder.
#
# KEY QUERIES:
#   - Get all active habits for a user (filtered, ordered)
#   - Check if user already has a habit with the same name
#   - Count active habits (for limit enforcement)
#   - Reorder habits (update sort_order for multiple rows)
#   - Soft delete (archive) instead of hard delete
# ============================================================================

from uuid import UUID

from sqlalchemy import func, select, update
from sqlalchemy.ext.asyncio import AsyncSession

from app.modules.habits.models import Habit
from app.shared.base_repository import BaseRepository


class HabitRepository(BaseRepository[Habit]):
    """
    Habit-specific database operations.

    Inherits CRUD from BaseRepository: create, get_by_id, update, delete.
    Adds: user-scoped queries, duplicate checks, reordering, soft delete.
    """

    def __init__(self, session: AsyncSession):
        super().__init__(Habit, session)

    async def get_user_habits(
        self,
        user_id: UUID,
        include_archived: bool = False,
    ) -> list[Habit]:
        """
        Get all habits for a user, ordered by sort_order.

        By default, excludes archived habits (soft-deleted).
        Pass include_archived=True for settings/management views.

        The ORDER BY sort_order ensures habits display in the user's
        preferred order (after drag-and-drop reordering).
        """
        query = select(Habit).where(Habit.user_id == user_id)

        if not include_archived:
            query = query.where(Habit.is_archived.is_(False))

        query = query.order_by(Habit.sort_order.asc(), Habit.created_at.asc())

        result = await self.session.execute(query)
        return list(result.scalars().all())

    async def get_user_habit(self, user_id: UUID, habit_id: UUID) -> Habit | None:
        """
        Get a specific habit — only if it belongs to this user.

        WHY user_id check:
            Without it, user A could access user B's habit by guessing the UUID.
            Always scope queries to the current user. This is called
            "row-level security" at the application layer.
        """
        result = await self.session.execute(
            select(Habit).where(
                Habit.id == habit_id,
                Habit.user_id == user_id,
            )
        )
        return result.scalar_one_or_none()

    async def name_exists_for_user(
        self,
        user_id: UUID,
        name: str,
        exclude_habit_id: UUID | None = None,
    ) -> bool:
        """
        Check if user already has an active habit with this name.

        exclude_habit_id is used during updates — don't flag the habit's
        own name as a duplicate when renaming.

        Example:
            User has "Water Intake" and "Sleep".
            Creating "Water Intake" → returns True (duplicate).
            Updating "Sleep" to "Sleep Hours" → exclude_habit_id=sleep_id.
        """
        query = select(func.count()).where(
            Habit.user_id == user_id,
            Habit.name == name,
            Habit.is_archived.is_(False),
        )

        if exclude_habit_id:
            query = query.where(Habit.id != exclude_habit_id)

        result = await self.session.execute(query)
        return result.scalar_one() > 0

    async def count_active_habits(self, user_id: UUID) -> int:
        """
        Count user's active (non-archived) habits.

        Used to enforce the maximum habit limit (20).
        Archived habits don't count toward the limit.
        """
        result = await self.session.execute(
            select(func.count()).where(
                Habit.user_id == user_id,
                Habit.is_archived.is_(False),
            )
        )
        return result.scalar_one()

    async def get_next_sort_order(self, user_id: UUID) -> int:
        """
        Get the next available sort_order value for a new habit.

        If user has habits with sort_order 0, 1, 2 → returns 3.
        New habits go at the end of the list.
        """
        result = await self.session.execute(
            select(func.coalesce(func.max(Habit.sort_order), -1)).where(
                Habit.user_id == user_id,
                Habit.is_archived.is_(False),
            )
        )
        return result.scalar_one() + 1

    async def reorder_habits(self, user_id: UUID, habit_ids: list[UUID]) -> None:
        """
        Update sort_order for multiple habits based on the provided order.

        The index in the list becomes the new sort_order:
            habit_ids[0] → sort_order = 0
            habit_ids[1] → sort_order = 1
            habit_ids[2] → sort_order = 2

        WHY not a single UPDATE:
            Each habit gets a DIFFERENT sort_order value.
            We batch this with individual updates in a single transaction.
            All updates commit together — if one fails, none apply.
        """
        for index, habit_id in enumerate(habit_ids):
            await self.session.execute(
                update(Habit)
                .where(Habit.id == habit_id, Habit.user_id == user_id)
                .values(sort_order=index)
            )
        await self.session.flush()

    async def archive_habit(self, user_id: UUID, habit_id: UUID) -> Habit | None:
        """
        Soft delete — set is_archived=True instead of actually deleting.

        The habit's log data is preserved. User can potentially unarchive later.
        This is the standard approach for data-heavy applications.
        """
        habit = await self.get_user_habit(user_id, habit_id)
        if not habit:
            return None

        habit.is_archived = True
        await self.session.flush()
        await self.session.refresh(habit)
        return habit
```

## 3. Line-by-Line Explanation

### Imports
```python
from sqlalchemy import func, select, update
```
- `func` — SQL aggregate functions: `func.count()` → `COUNT(*)`, `func.max()` → `MAX(...)`, `func.coalesce()` → `COALESCE(...)`
- `select` — builds SELECT queries
- `update` — builds UPDATE queries (new in this repo — auth only used select)

### `get_user_habits()` — The Dashboard Query

```python
query = select(Habit).where(Habit.user_id == user_id)

if not include_archived:
    query = query.where(Habit.is_archived.is_(False))

query = query.order_by(Habit.sort_order.asc(), Habit.created_at.asc())
```

- **Dynamic query building** — start with a base query, then conditionally add filters. This is a powerful pattern:
  ```python
  query = select(Habit).where(...)      # Base query
  if condition:
      query = query.where(...)          # Add filter conditionally
  query = query.order_by(...)           # Always add ordering
  ```
- `Habit.sort_order.asc()` — `ORDER BY sort_order ASC` (lowest first = top of dashboard)
- `Habit.created_at.asc()` — secondary sort: if two habits have the same sort_order, order by creation date
- `include_archived=False` (default) → dashboard view. `True` → settings page

### `get_user_habit()` — Row-Level Security

```python
select(Habit).where(
    Habit.id == habit_id,
    Habit.user_id == user_id,
)
```

- **Two conditions:** Both `id` AND `user_id` must match
- If user A tries to access user B's habit by guessing the UUID, the query returns `None` (user_id won't match)
- The service layer converts `None` to `HabitNotFoundError(404)` — indistinguishable from "habit doesn't exist"
- This is **application-level row-level security** — every query is scoped to the authenticated user

### `name_exists_for_user()` — Duplicate Check with Exclusion

```python
query = select(func.count()).where(
    Habit.user_id == user_id,
    Habit.name == name,
    Habit.is_archived.is_(False),
)

if exclude_habit_id:
    query = query.where(Habit.id != exclude_habit_id)
```

- `select(func.count())` → `SELECT COUNT(*)` — we only need the count, not the actual habits
- Three conditions: same user, same name, not archived. Archived habits can have the same name
- `exclude_habit_id` — used when UPDATING a habit. If you rename "Sleep" to "Sleep" (no change), it shouldn't be flagged as a duplicate. We exclude the habit's own ID from the check
- `Habit.id != exclude_habit_id` → `WHERE id != ?` — "find duplicates, but not myself"

### `count_active_habits()` — Limit Enforcement

```python
select(func.count()).where(
    Habit.user_id == user_id,
    Habit.is_archived.is_(False),
)
```

- Simple count: how many non-archived habits does this user have?
- Service checks: `if count >= 20: raise HabitLimitExceededError()`
- Archived habits don't count — user can archive old habits to make room for new ones

### `get_next_sort_order()` — The COALESCE Trick

```python
select(func.coalesce(func.max(Habit.sort_order), -1)).where(...)
```

- `func.max(Habit.sort_order)` → `MAX(sort_order)` — finds the highest sort_order
- **Problem:** If the user has NO habits, `MAX()` returns `NULL`
- `func.coalesce(..., -1)` → `COALESCE(MAX(sort_order), -1)` — if the result is NULL, use -1 instead
- Then `+ 1` → if max is 2, return 3. If max is NULL (no habits), return 0 (-1 + 1)
- **COALESCE** is an SQL function that returns the first non-NULL argument. It's the SQL equivalent of Python's `value or default`

### `reorder_habits()` — Batch Update

```python
for index, habit_id in enumerate(habit_ids):
    await self.session.execute(
        update(Habit)
        .where(Habit.id == habit_id, Habit.user_id == user_id)
        .values(sort_order=index)
    )
await self.session.flush()
```

- `enumerate(habit_ids)` — gives both the index (0, 1, 2...) and the habit_id
- `update(Habit).where(...).values(sort_order=index)` → `UPDATE habits SET sort_order = 0 WHERE id = ? AND user_id = ?`
- Each habit gets a DIFFERENT sort_order based on its position in the array
- `user_id` check in WHERE — prevents a user from reordering another user's habits
- `flush()` at the end — all updates are sent as one batch. The service calls `commit()` to finalize

### `archive_habit()` — Soft Delete

```python
habit = await self.get_user_habit(user_id, habit_id)
if not habit:
    return None

habit.is_archived = True
await self.session.flush()
await self.session.refresh(habit)
return habit
```

- First, fetch the habit (with user_id check)
- If not found → return `None` (service raises 404)
- Set `is_archived = True` — SQLAlchemy tracks this change
- `flush()` → generates `UPDATE habits SET is_archived = true WHERE id = ?`
- `refresh()` → reload from DB to get `updated_at` (set by `onupdate` trigger)
- The habit and all its log data remain in the database — only hidden from the dashboard

## 7. Interview Q&A

### Q1: How do you prevent one user from accessing another user's habits?
**A:** "Every repository method includes `WHERE user_id = ?` using the authenticated user's ID from the JWT token. There's no method that queries habits without a user_id filter. Even if someone guesses another user's habit UUID, the query returns nothing because the user_id won't match. The service layer converts the None result to a 404 error — indistinguishable from a non-existent habit. This is application-level row-level security."

### Q2: Explain the COALESCE trick in get_next_sort_order.
**A:** "When a user has no habits yet, `MAX(sort_order)` returns NULL — and `NULL + 1` is still NULL in SQL. `COALESCE(MAX(sort_order), -1)` returns -1 when there are no habits, so `-1 + 1 = 0` — the first habit gets sort_order 0. It's a common SQL pattern for handling edge cases with aggregate functions."

### Q3: Why do you check name_exists with exclude_habit_id during updates?
**A:** "When a user updates a habit without changing the name, we still run the duplicate check. Without exclusion, the habit would find ITSELF as a 'duplicate' and reject the update. The `exclude_habit_id` parameter adds `WHERE id != ?` to exclude the habit being updated. This way, only OTHER habits with the same name trigger the conflict."

### Q4: How does the reorder operation work? Is it atomic?
**A:** "The frontend sends an array of habit IDs in the desired order. We loop through with `enumerate()` and set `sort_order = index` for each. All updates are in the same SQLAlchemy session — `flush()` sends them to the database, and `commit()` in the service layer finalizes the transaction. If any update fails, the entire batch rolls back. This guarantees consistency — you never end up with a partially reordered list."
